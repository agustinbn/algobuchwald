## División y Conquista (D&C)

- Hasta ahora: recursión "de a uno" (ver un caso, llamar recursivamente para el resto). Ej: máximo de un arreglo, factorial.
- D&C: dividir el problema en **proporciones** (no de a uno), resolver cada parte recursivamente, y combinar resultados.
- Ejemplo ya conocido de D&C: **búsqueda binaria**.

```go
func busquedaBinaria(arreglo []int, inicio, fin, elemento int) int {
    if inicio > fin {
        return -1
    }
    medio := (inicio + fin) / 2
    if arreglo[medio] == elemento {
        return medio
    } else if arreglo[medio] < elemento {
        return busquedaBinaria(arreglo, medio+1, fin, elemento)
    } else {
        return busquedaBinaria(arreglo, inicio, medio-1, elemento)
    }
}
```

### Máximo de un arreglo por D&C

Caso base: un solo elemento. Caso general: partir al medio, calcular el máximo de cada mitad recursivamente, devolver el mayor de los dos.

```python
def maximo(arreglo, inicio, fin):
    if inicio == fin:
        return arreglo[inicio]
    medio = (inicio + fin) // 2
    max_izq = maximo(arreglo, inicio, medio)
    max_der = maximo(arreglo, medio + 1, fin)
    return max_izq if max_izq > max_der else max_der
```

## Ordenamientos con D&C

### Mergesort

- Caso base: un elemento (o ninguno).
- Caso general: ordenar mitad izquierda, ordenar mitad derecha, **intercalar** ordenadamente ambos resultados.

```python
def mergesort(arr, largo):
    if largo == 1:
        return arr
    medio = largo // 2
    primera_ordenada = mergesort(arr[0:medio], medio)
    segunda_ordenada = mergesort(arr[medio:largo], largo - medio)
    return insertar_ordenado(primera_ordenada, medio, segunda_ordenada, largo - medio)
```

### Quicksort

- Caso base: un elemento (o ninguno).
- Caso general: elegir un **pivote** (idealmente aleatorio), separar en dos arreglos auxiliares (menores y mayores al pivote), ordenar ambos recursivamente y unir.
- **Problema**: si el pivote elegido siempre es el menor/mayor (ej. arreglo ya ordenado y pivote = primer elemento), una de las particiones queda vacía en cada paso → degenera en complejidad cuadrática. Por eso conviene elegir el pivote al azar.

## Teorema Maestro

- Calcular a mano la complejidad de algoritmos iterativos o recursivos simples es fácil; para D&C puede ser complicado. El Teorema Maestro da un atajo.
- Aplica a algoritmos cuya ecuación de recurrencia sea de la forma:

  **T(n) = A·T(n/B) + O(n^C)**

  - **A**: cantidad de llamados recursivos.
  - **B**: proporción del tamaño original con la que se llama recursivamente.
  - **O(n^C)**: costo de partir y juntar (todo lo que no son los llamados recursivos).

- **Casos** (comparando `C` contra `log_B(A)`):
  - Si `C < log_B(A)` → `T(n) = Θ(n^(log_B A))`
  - Si `C = log_B(A)` → `T(n) = Θ(n^C · log n)`
  - Si `C > log_B(A)` → `T(n) = Θ(n^C)`

- **Cuidado**: sólo sirve para D&C (si no, no existe el término B). Es una versión simplificada, pero cubre casi todos los casos reales y todos los de la materia.

### Ejemplos

- **Mergesort**: `A=2, B=2, C=1` → `log_2(2) = 1 = C` → caso 2 → `Θ(n log n)`.
- **Búsqueda binaria**: aunque el código tenga dos llamados recursivos escritos, en cada ejecución sólo se llama a **uno** de los dos (nunca ambos), entonces `A=1, B=2, C=0` → `log_2(1) = 0 = C` → caso 2 → `Θ(log n)`.
- **Máximo por D&C**: `A=2, B=2, C=0` → `log_2(2) = 1 > C` → caso 1 → `Θ(n)`. Mismo orden que la versión secuencial/iterativa → usar D&C acá no mejora nada, sólo lo justifica cuando el algoritmo lineal es realmente mejor o más simple.

## Complejidad espacial

- No sólo importa el tiempo: la recursión también consume memoria (pila de llamados). Se mencionó como concepto a tener en cuenta al elegir un algoritmo.

## Caso de estudio: padrón electoral

Comparar, para hacer **K** búsquedas sobre un arreglo desordenado:
- **K búsquedas lineales**: costo `O(K·n)`.
- **1 ordenamiento + K búsquedas binarias**: costo `O(n log n + K log n) = O((n+K) log n)`.

- Si `K` es chico, conviene la búsqueda lineal repetida; si `K` es grande, conviene ordenar una vez y usar búsqueda binaria.
- Punto de quiebre (asumiendo `n ≥ K`): `O(K·n) = O(n log n) → K = O(log n)`.
  - Si `K` está por debajo de `O(log n)`, conviene búsqueda lineal repetida.
  - Si `K` supera `O(log n)`, conviene ordenar una vez y buscar binario.
