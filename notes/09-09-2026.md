# Ordenamientos Comparativos y no Comparativos

---

## Ordenamientos comparativos

- Ordenan comparando elementos entre sí.
- Ejemplos: Selección, Inserción, Mergesort, Quicksort, Burbujeo (todos los vistos hasta ahora).

## Cota mínima de complejidad (comparativos)

- Se analiza para algoritmos que no usan información adicional (sólo comparaciones).
- La complejidad está relacionada con la altura del **árbol de decisión** de comparaciones (cada nodo es una comparación, cada hoja un ordenamiento posible).
- Cantidad de hojas del árbol: `n!` (todas las permutaciones posibles).
- Altura del árbol: `h = log(#nodos)`.
- En el último nivel de un árbol binario hay a lo sumo `2^h` nodos, entonces:
  - `2^h ≥ n! → h ≥ log(n!) → h = Ω(log n!)`
  - Como `n! ≤ n^n`: `h = Ω(log n!) = Ω(log(n^n)) = Ω(n log n)`

**Conclusión:** un algoritmo de ordenamiento comparativo no puede ser mejor que `Ω(n log n)`.

## Ordenamientos no comparativos

- Ordenan **sin comparar** elementos entre sí, usando información adicional sobre los datos.
- No se pueden aplicar siempre: sólo cuando se tiene esa información adicional (ej. rango acotado de valores).
- Al no comparar, pueden superar la cota de `n log n`.

**Algoritmos a ver:**
- Counting Sort
- Radix Sort
- Bucket Sort
