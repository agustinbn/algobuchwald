## Listas e Iteradores

### Repaso: lista enlazada
- Primitivas: insertar primero/último, ver primer/último, borrar primero, está vacía, largo.
- No se plantea "borrar último": en una lista simplemente enlazada requiere recorrer hasta el anteúltimo (O(n)).

### Iteradores
Un **iterador** es un mecanismo que provee un TDA para recorrer su contenido **sin conocer la estructura interna**.

**Ventajas:**
- Abstrae cómo está implementado el TDA.
- Forma genérica (interfaz) de acceder a los datos.
- Si el TDA cambia, quien itera no necesita cambiar su código.

**Desventaja:** el que implementa el TDA tiene más trabajo.

Hay 2 tipos:
- **Externos**: estructura externa (más control).
- **Internos**: lo hace el mismo TDA (más simple).

### Iteradores externos
- Usan de forma explícita una **estructura auxiliar** que hace la iteración.
- **No es genérico**: su implementación está atada al TDA que itera.
- Primitivas principales: `HayAlgoMas`, `VerActual`, `Avanzar`.
- Particulares para la lista: `Insertar`, `Borrar`.
- Lo crea y maneja paso a paso quien usa el TDA.

**Preguntas:**
- ¿Se puede modificar la lista mientras se la itera (con primitivas del TDA, no del iterador)?
- ¿Si implemento una primitiva de la lista, puedo usar el iterador externo?

### Iteradores internos
- El TDA se sabe iterar a sí mismo (es una **primitiva del TDA**). Más simple, menos control, sin estructura extra.
- No se "crea", no se maneja paso a paso: se invoca `tda.Iterar(visitar)` y el TDA se itera.

```go
// Lado de quien implementa el TDA
func (tda TDA[T]) Iterar(visitar func(T) bool) {
    // depende de lo que sea el TDA
}
```

`visitar` la define quien usa el TDA; devuelve `true` para seguir y `false` para cortar.

**Ejemplos (lado del usuario):**
```go
// Imprimir
lista.Iterar(func(v int) bool {
    fmt.Println(v)
    return true
})

// Suma de elementos
contador := 0
lista.Iterar(func(v int) bool {
    contador += v
    return true
})

// Imprimir los primeros 5 (variable externa + condición de corte)
contador := 0
lista.Iterar(func(v int) bool {
    contador += 1
    fmt.Println(v)
    return contador < 5
})

// Sumar los primeros 5 números pares
suma, cont := 0, 0
lista.Iterar(func(v int) bool {
    if cont == 5 {
        return false
    }
    if v%2 == 0 {
        suma += v
        cont += 1
    }
    return true
})
```

**Repaso:**
- ¿`visitar` debe estar definida por quien usa el TDA? Sí.
- ¿Puede controlar hasta dónde itera? Sí, con el valor booleano que devuelve.
- ¿Se puede usar el iterador externo para hacer el interno? Sí.
- ¿El iterador interno puede borrar o agregar elementos? No (no tiene acceso a esas operaciones de la posición).
- ¿Hay que implementar ambos para la Lista? Sí, en el TP se piden los dos.

## TDA Diccionario

**Utilidad:** asociar un valor a una clave.
- "nombre" → "cumpleaños" (Martín → 19/11; Ezequiel → 31/03; ...).
- "receta" → lista de ingredientes (Milanesa → [nalga, sal, huevo, provenzal, pan rallado]).

**Primitivas principales:** guardar, borrar, ver si una clave pertenece, obtener el valor asociado a una clave.

**TDA Conjunto:** las mismas (sin valor asociado en la práctica) + unión, intersección, diferencia, diferencia simétrica.

### Mapa de bits
Arreglo de booleanos indexado por clave (ej. senadores que hacen "check in"/"check out": `T` en la posición al entrar, `F` al salir). Lo que importa es el concepto: si las claves fueran números del 0 al n, se accede directo por índice.

**Problema:** las claves no son números (principalmente cadenas). **Solución:** transformar cadenas (u otro tipo) en números → **tablas de hashing**.

### Funciones de hashing
Toman una clave y la transforman en un **índice numérico válido**.

**Características:**
- Distribuir uniformemente.
- Ser rápida.
- Determinística (misma clave → mismo resultado).

Con una buena función, las operaciones principales del hash son **O(1)**.

**Ejemplo 1: sumar caracteres**
```go
func hashSuma(clave string, largo int) int {
    suma := 0
    for _, c := range clave {
        suma += int(c)
    }
    return suma % largo   // % largo para quedar en rango (idealmente largo primo)
}
```

**Ejemplo 2: FNV**
```
h := 14695981039346656037
por cada c en clave:
    h *= 1099511628211
    h ^= int(c)
return h % largo
```

**Ejemplo 3: Jenkins**
```
por cada caracter:
    hash += s[i]
    hash += (hash << 10)
    hash ^= (hash >> 6)
hash += (hash << 3)
hash ^= (hash >> 11)
hash += (hash << 15)
return hash % largo
```

**Funciones de hashing criptográficas** (MD5, SHA256):
- Mínimas colisiones: muy difícil encontrar X e Y tal que H(X) == H(Y).
- Dado H(X), muy difícil obtener X.
- Un cambio mínimo en la clave produce un cambio significativo en la salida.

### Colisiones
Dos claves distintas caen en la misma posición. Estrategias:
- **Hash cerrado**: se aplica una función de dispersión para definir la nueva posición.
- **Hash abierto**: en cada posición de la tabla se guarda una lista.

Ejemplo usado: `f_hash("Eli")=3, ("Facu")=5, ("Taiel")=3, ("Eze")=4, ("Fede")=9, ("Martina")=9`, tabla de 10.

### Hash cerrado
- Si la posición está ocupada, se prueba la siguiente (probing lineal): Taiel (3 ocupado) → 4; Eze (4 ocupado) → 6; Martina (9 ocupado) → 0 (circular).
- **Búsqueda:** ir a `hash(clave)` y seguir hasta encontrarla o llegar a una posición vacía.
- **Borrados:** si se deja vacía la celda de "Eli", buscar a Taiel fallaría (corta en vacío). Cada celda necesita **clave, valor y estado**: `VACIO`, `OCUPADO`, `BORRADO`. Al buscar, se sigue de largo por las celdas `BORRADO`.

### Hash abierto
- Cada posición guarda una **lista** de elementos (Eli, Taiel en la 3; Fede, Martina en la 9).
- **Búsqueda:** ir a la posición y recorrer la lista.
- **Borrado:** se borra el nodo de la lista; no hacen falta estados.

### Redimensión
Hay que definir cuándo conviene redimensionar. **Factor de carga:** `α = n / M` (n = elementos en la tabla, M = capacidad).
- **Hash cerrado:** buena métrica `α < 0,7`. Se pueden contar también los `BORRADO` en la carga.
- **Hash abierto:** puede tener `α > 1`. Hay que probar; entre 2 y 3 suele ser buena opción.
- ⚠️ **No se puede reutilizar la tabla** (ni append, ni make + copy): al cambiar M cambia el resultado de `hash % M`, hay que **reinsertar** todos los elementos.

## Otras resoluciones de colisiones

### Hash cerrado: tipos de probing
- **Lineal** (de a uno): `pos = hash(x) + #colisiones`
- **Cuadrático:** `pos = hash(x) + (#colisiones)²`
- **Doble hashing:** `pos = hash1(x) + #colisiones · hash2(x)`

### Hopscotch Hashing (rayuela)
- Parámetro **K**: cuán lejos de `hash(X)` puede quedar X. Con K = 4 se ubica en `hash(X)`, `+1`, `+2` o `+3`.
- Si hay lugar libre entre esas posiciones → se ubica.
- Si no, se busca la siguiente posición libre y se va **hacia atrás** viendo si se pueden reubicar elementos para acercar el lugar libre.
- Si no es posible ninguna reubicación → **redimensión**.

Ejemplo: tabla de 10, K = 3; `Dato=3, Jorge=5, Cami=3, Nacho=4, Jas=1, Mati=3, Agustín=4`.
- Dato → 3, Jorge → 5, Cami → 4 (3 ocupado), Nacho → 6 (4 ocupado, 5 ocupado, 6 libre), Jas → 1.
- Mati (hash 3): libre más cercana es la 7 (fuera de rango K=3); se reubica Jorge de 5 a 7 (su hash es 5, dentro de K), y Mati queda en 5.
- Agustín (hash 4): según las diapos, Dato se mueve de la posición 3 a la 2 y Agustín queda en la 3.

**Consecuencias:**
- Las búsquedas son siempre **O(1)** (hay a lo sumo K posiciones).
- Con una mala función de hashing, guardar crece mucho (casi seguro O(n)) o es inusable (redimensión constante).
- No hacen falta los borrados (estado `BORRADO`).

### Cuckoo Hashing
- Se usan **múltiples funciones de hashing**; cada una da una posición alternativa para cada elemento.
- **Búsqueda:** el elemento, si está, está en alguna de las posiciones que indica cada función.
- **Inserción:** se inserta en su primera alternativa. Si había algo, ese algo se mueve a su siguiente alternativa; si ahí había otro, se repite la lógica, hasta terminar o entrar en un loop (→ redimensionar).

Ejemplo: tabla de 10, 2 funciones.
```
Dato:  h1=3 h2=5     Jorge: h1=5 h2=9     Cami: h1=3 h2=9
Nacho: h1=4 h2=0     Jas:   h1=1 h2=8     Mati: h1=3 h2=4
```
Resultado final: `0:Nacho[2], 1:Jas[1], 3:Dato[1], 4:Mati[2], 5:Jorge[1], 9:Cami[2]`.

**Consecuencias:**
- Acepta mayor factor de carga a medida que se agregan funciones de hashing.
- No hacen falta los borrados.
- Se puede combinar con la idea de hash abierto (buckets).
- Se puede agregar un sector de **stash**.
- Se puede averiguar de antemano si un elemento se va a poder guardar.
